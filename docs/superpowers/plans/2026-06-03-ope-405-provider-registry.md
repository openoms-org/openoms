# OPE-405 Provider Registry, Versioning, Lifecycle & Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development / executing-plans. Steps use `- [ ]`.

**Goal:** Build the provider registry data model + lifecycle state machine + publication audit + tenant private-beta enablement that the Provider Integration Studio is built on, gated behind the OPE-404 platform-admin boundary.

**Architecture:** Four non-tenant-scoped tables (`provider_definitions`, `provider_versions`, `provider_publication_events`, `provider_tenant_enables`), a `ProviderPublicationService` that enforces the lifecycle transition graph + immutability of published versions + emergency disable/rollback, repositories on the pool (no RLS), and platform endpoints under `/v1/platform/providers` each guarded by `RequirePlatformPermission`.

**Tech Stack:** Go 1.25, chi/v5, pgx/v5, golang-migrate, testify. Builds on OPE-404 (`platform_admins`, `RequirePlatformAdmin/Permission`, `/v1/platform` group).

---

## Scope

In scope: provider definitions (family metadata) + versions (immutable once published) + lifecycle state machine + publication event audit trail + tenant private-beta allowlist + emergency disable/rollback. Endpoints: list/create/read/patch definitions, create/read versions, publish (state transition), enable-tenant.

Out of scope (later tasks): credential/settings schema (OPE-406), capability profiles + status mappings (OPE-407), validation probes/runs/gaps (OPE-408), Studio UI (OPE-409-411), the customer-facing tenant-setup read path.

## Lifecycle state machine (authoritative — design spec §570)

```
research → designed → adapter_in_progress → internal_validation → private_beta → available → deprecated → retired
internal_validation → designed        (gaps found)
private_beta        → internal_validation  (beta issue)
available           → internal_validation  (regression / emergency disable)
```
`retired` is terminal. Transitions enforced in `ProviderPublicationService`; any other transition → 422.

## Data model (migration 000032) — all NON-tenant-scoped, NO RLS (platform-managed)

```sql
CREATE TABLE public.provider_definitions (
    id                         uuid PRIMARY KEY DEFAULT public.uuid_generate_v4(),
    provider_key               text NOT NULL UNIQUE,
    display_name               text NOT NULL,
    provider_type              text NOT NULL,   -- marketplace|carrier|supplier|shop|invoicing|edi|other (CHECK)
    regions                    text[] NOT NULL DEFAULT '{}'::text[],
    business_domains           text[] NOT NULL DEFAULT '{}'::text[],
    owner                      text NOT NULL DEFAULT '',
    source_links               jsonb NOT NULL DEFAULT '[]'::jsonb,
    notes                      text NOT NULL DEFAULT '',
    latest_published_version_id uuid,           -- FK added after provider_versions (points to the current 'available')
    created_at                 timestamptz NOT NULL DEFAULT now(),
    updated_at                 timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE public.provider_versions (
    id                     uuid PRIMARY KEY DEFAULT public.uuid_generate_v4(),
    provider_definition_id uuid NOT NULL REFERENCES public.provider_definitions(id) ON DELETE CASCADE,
    version                text NOT NULL,
    publication_state      text NOT NULL DEFAULT 'research',  -- CHECK over the 8 states
    changelog              text NOT NULL DEFAULT '',
    compatibility_notes    text NOT NULL DEFAULT '',
    created_by             uuid REFERENCES public.users(id) ON DELETE SET NULL,
    published_by           uuid REFERENCES public.users(id) ON DELETE SET NULL,
    published_at           timestamptz,
    created_at             timestamptz NOT NULL DEFAULT now(),
    updated_at             timestamptz NOT NULL DEFAULT now(),
    UNIQUE (provider_definition_id, version)
);
ALTER TABLE public.provider_definitions
    ADD CONSTRAINT provider_definitions_latest_version_fkey
    FOREIGN KEY (latest_published_version_id) REFERENCES public.provider_versions(id) ON DELETE SET NULL;

CREATE TABLE public.provider_publication_events (
    id                 bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    provider_version_id uuid NOT NULL REFERENCES public.provider_versions(id) ON DELETE CASCADE,
    from_state         text,
    to_state           text NOT NULL,
    action             text NOT NULL DEFAULT 'transition',  -- transition|emergency_disable|create
    actor_user_id      uuid REFERENCES public.users(id) ON DELETE SET NULL,
    reason             text NOT NULL DEFAULT '',
    metadata           jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_at         timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_provider_pub_events_version ON public.provider_publication_events (provider_version_id, created_at DESC); -- migrate:index-lock-ok

CREATE TABLE public.provider_tenant_enables (
    id                  uuid PRIMARY KEY DEFAULT public.uuid_generate_v4(),
    provider_version_id uuid NOT NULL REFERENCES public.provider_versions(id) ON DELETE CASCADE,
    tenant_id           uuid NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
    enabled_by          uuid REFERENCES public.users(id) ON DELETE SET NULL,
    created_at          timestamptz NOT NULL DEFAULT now(),
    UNIQUE (provider_version_id, tenant_id)
);
CREATE INDEX idx_provider_tenant_enables_tenant ON public.provider_tenant_enables (tenant_id); -- migrate:index-lock-ok
```
Plus dual-role grants DO-block (openoms_app/openoms) for the four tables + sequences (mirror migration 000031). `.down.sql` drops in FK-safe order (publication_events, tenant_enables, drop the definitions→versions FK, versions, definitions).

Design note: `provider_definitions.publication_state` from the spec is NOT stored (it would denormalize/drift); the lifecycle lives on `provider_versions.publication_state`, and the definition keeps `latest_published_version_id` (the version currently `available`). `provider_tenant_enables` is platform-managed (no RLS); the customer-side read path is a later task (SECURITY DEFINER function), so RLS here would break platform cross-tenant writes.

## Risks
- **Transition correctness** — the state graph is the security/correctness core; cover every edge with table-driven tests + integration walk.
- **latest_published_version_id consistency** — set/clear atomically with the version state change (same logical operation; acceptable to do as sequential pool writes since platform traffic is low and single-writer per provider in practice). Note the small race; a follow-up can wrap in a tx if needed.
- **Migration Safety CI** — indexes carry `-- migrate:index-lock-ok` (new empty tables); keep the literal phrase "CREATE INDEX" out of comments.

## Rollback Notes
`migrate down` drops the four tables (drop publication_events + tenant_enables first, then the definitions→versions FK, then versions, then definitions). Endpoints are gated by the existing `deps.PlatformAdmin != nil` platform group.
