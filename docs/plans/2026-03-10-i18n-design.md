# Internationalization (i18n) — Design

**Date:** 2026-03-10
**Status:** Approved

## Goal

Make OpenOMS multi-language. Default language detected from browser/system, user can override and save preference. Start with English + Polish, architecture supports adding more languages.

## Architecture

### Language Detection Priority

1. User preference from API (`users.language` column) — synced to localStorage after login
2. `Accept-Language` browser header (before login / new user / preference not set)
3. Fallback: `en`

### Frontend

- **Library:** `next-intl` (without locale in URL — no `/en/orders` vs `/pl/orders`)
- **Translation files:** `apps/dashboard/messages/{en,pl}.json`
- **Namespaces:** `common`, `orders`, `products`, `shipments`, `returns`, `customers`, `invoices`, `settings`, `integrations`, `warehouses`, `navigation`, `validation`, `errors`
- **Pattern:** `const t = useTranslations('orders'); t('status.confirmed')` → "Confirmed" / "Potwierdzone"

### Backend

- **Language-agnostic** — returns keys instead of Polish text
- Error responses: `{"error": "plan.user_limit_reached", "error_params": {"max": 5}}`
- Status labels, role names, carrier services — all as enum keys, frontend translates
- No `Accept-Language` processing on backend

### User Preference Storage

- **Database:** `ALTER TABLE users ADD COLUMN language VARCHAR(5)` (nullable, null = auto-detect)
- **API:** `GET /v1/users/me` returns `language`, `PATCH /v1/users/me` accepts `language`
- **localStorage:** Cache after login for instant load without API round-trip
- **UI:** Language picker in profile settings

## Scope

| Layer | Change | Scale |
|-------|--------|-------|
| DB migration | Add `language` column to `users` | 1 file |
| API model/handler | Add `language` to user model + update endpoint | ~3 files |
| API responses | Replace Polish strings with keys | ~34 Go files |
| Frontend setup | `next-intl` provider, locale detection, messages | ~5 new files |
| Frontend strings | Extract hardcoded Polish to translation files | ~186 files |
| UI | Language picker in settings | 1 component |

## Translation File Structure

```
apps/dashboard/messages/
  en.json    ~500+ keys
  pl.json    ~500+ keys (current Polish text, extracted)
```

Flat dot-notation keys grouped by namespace:
```json
{
  "common.save": "Save",
  "common.cancel": "Cancel",
  "common.delete": "Delete",
  "orders.status.confirmed": "Confirmed",
  "orders.status.processing": "Processing",
  "errors.plan.user_limit_reached": "User limit reached (max: {max})",
  "navigation.dashboard": "Dashboard",
  "navigation.orders": "Orders"
}
```

## What We Don't Do

- No locale prefixes in URL
- No SSR/Server Component translations (client-side only)
- No translation of user content (product names, order notes)
- No auto-translation (AI/Google Translate)
- No backend-side translation
